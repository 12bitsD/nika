# nika requirements map

This map records accepted product requirements and their minimalist verification targets. N1–N10 are the single-agent foundation (2026-11-06); N11–N13 extend Nika into the personal superagent harness (2026-11-24).

| ID | Requirement and user value | Authoritative design | Status and acceptance required |
|---|---|---|---|
| N1 | Talk privately, in Threads, and at document comments with cross-entry recall | [Proactive & Feishu](../design/proactive-and-feishu.md) | **Design closed.** Feishu allowlist, dedupe, raw SQLite `session_ctl(action="recent" \| "inspect")`, and Single Live Status Card |
| N2 | Read and edit Feishu documents/comments reliably | [Comment-as-Anchor & Doc Edits](../design/proactive-and-feishu.md#2-feishu-documents--comments-comment-as-anchor--read-back-verification) | **Design closed.** Auto-sliced comment context (±2 paragraphs), section replacement, and mandatory read-back check |
| N3 | Complete chat and coding through one execution path and deep tools | [System Prompt](../design/system-prompt.md) | **Design closed.** Consolidated deep tool catalog (`read` handles files, directories, and Wiki; `exclusive` failures truncate remaining batch calls) |
| N4 | Directly reuse `nextloop` without pass-through wrappers | [Adapter contract](nextloop-adapter.md) | **Design closed.** Direct use of `nextloop` SQLite/Context/Provider; product seams limited to channel adapters, deterministic scheduler, and `NikaToolRuntime` |
| N5 | Recall and connect long-term knowledge (`src/nika/wiki.py` + `skills/wiki/SKILL.md`) | [Dual-repo Wiki](../design/agentwiki.md) | **Design closed.** Mounts existing work + personal Wiki repos directly; static core aliases in `AGENTS.md`, sub-5ms `ripgrep` H2-TOC `wiki(action="search")`, and `read` |
| N6 | Proactively curate Wiki knowledge while protecting behavior files | [Wiki writes](../design/agentwiki.md#4-native-git-backed-optimistic-writes--single-line-receipt-wikiactionupsert--revert) | **Design closed.** Per-repo Git-committed `wiki(action="upsert")` + single-line receipt; OS `chmod 444` on `AGENTS.md` and `skills/**` |
| N7 | Use container Browser and desktop safely | [ADR-0002](../adr/0002-single-agent-loop.md) | **Design closed.** Unified `gui(target="browser" \| "desktop")` serialized by `gui_lock` |
| N8 | Maintain a damped WorkingContext reminder and sharp Compaction | [Compaction Prompt](../design/compaction-prompt.md) | **Design closed.** 200-word 4-part Compaction Prompt + `nextloop` WorkingContext damping |
| N9 | Reduce cognitive load via deterministic Proactive mechanisms | [Proactive protocol](../design/proactive-and-feishu.md#3-three-part-proactive-protocol-cognitive-offloading-zero-spam) | **Design closed.** Ingress Pre-Hydration, Optimistic Wiki Sync with Receipt, and Single Live Status Card |
| N10 | Keep trust, locks, storage, and export simple | [Occam's Razor cuts](../design/proactive-and-feishu.md#4-occams-razor-cuts) | **Design closed.** Feishu `allowlist`, `chmod 444`, 2 container locks (`gui_lock`, `wiki_git_lock`), single-file SQLite backup, and `nika export` CLI |
| N11 | Connect Pocket and future apps via one internal envelope without core branching | [Harness §2 & §5](../design/harness.md) | **Design closed.** Thin `PocketAdapter` (`/webhooks/pocket` → `202` + one-time callback, silent on Feishu unless reminded/blocked); native `pocket(method, params)` RPC tool with no MCP wrapper |
| N12 | Run `1 main + 4 specialists` behind one Nika identity with low-latency follow-ups | [Harness §4](../design/harness.md) | **Design closed.** Read-only specialist config packs, 1-hop `threads` binding, Task Session recycling, and 3 internal tools (`dispatch_task`, `report_task`, blind `consult_peer` locked at `depth=1`) |
| N13 | Persist scheduler state deterministically without external infrastructure | [Harness §3](../design/harness.md) | **Design closed.** Shared WAL `nika.db` with exactly 3 Nika tables (`ingress_events`, `threads`, `tasks`); no Redis, Postgres, or MQ |
